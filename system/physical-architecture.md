# Physical architecture

The **physical view** of the vehicle's architecture ([method.md](method.md)): the system elements the vehicle is built
from and the connections between them. The **logical view** of the same architecture is the
[logical architecture](renders/Nexus-Platform-Logical-Architecture.svg). Both describe the same level, the vehicle; they
are related by **allocation**, and neither is above the other (ISO/IEC/IEEE 42010: views related by correspondences).

**The drawing owns the list of elements**: [Nexus-Platform-Physical-Architecture](renders/Nexus-Platform-Physical-Architecture.svg),
generated by [`scripts/Nexus-Platform-Physical-Architecture.py`](scripts/Nexus-Platform-Physical-Architecture.py). Every
element has its own ID, `Nexus-Phys-NN`, never reused. Parts belong to [`../bom/BOM.md`](../bom/BOM.md), wiring and placement
to [`../hardware/README.md`](../hardware/README.md) and the decisions; the drawing names them and restates none of it.

## Relation to the logical view

Allocation is done function by function, and it is the next step. Before it, the comparison of the two views already
shows two patterns:

| Pattern | Physical element | Logical component | What it means |
|---|---|---|---|
| **Realises one component** | `Nexus-Phys-05` Power supply and distribution | 101 Energy Storage & Distribution | Most of the component's functions land on this one element. Not all: 101's state-of-charge estimate will run on a node, and SW1 also serves 501 as the emergency stop (HW-08). The two keep their own IDs |
| | `Nexus-Phys-06` Chassis and enclosure | 102 Structure & Enclosure | |
| | `Nexus-Phys-07` Rear drive | 201 Propulsion | |
| | `Nexus-Phys-08` Steering actuator | 202 Steering | |
| | `Nexus-Phys-04` Vehicle CAN bus | 401 In-Vehicle Communication | The physical layer only; 401's later functions are software on the nodes |
| | `Nexus-Phys-09` Perception sensors | 301 Environment Perception | Sensing only; detection runs on the Pi 5 |
| **Hosts many components** | `Nexus-Phys-01` STM32 node, `Nexus-Phys-02` FRDM node, `Nexus-Phys-03` Pi 5 node | 203, 302, 303, 402, 403, 501, 502, 503, 504, and parts of the others | Software on a node. Only allocation says which function goes where |

## Not an element yet

- **The IMU** joins in Phase 2 only if it is bought ([phases.md](phases.md)); its connection is undecided.
- **Operator controls beyond SW1 and SW2.** Phase 2 puts vehicle status on the fascia LEDs; which hardware does that is open.
- **The Pi 5's power, mounting and network** wait for their own `HW` and `MEC` entries, as the phase plan says.
