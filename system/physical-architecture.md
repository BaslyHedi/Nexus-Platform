# Physical architecture

The L2 view of [method.md](method.md): what the vehicle is built from. **The drawing owns the list of elements**,
[Nexus-Platform-Physical-Architecture](renders/Nexus-Platform-Physical-Architecture.svg), generated by
[`scripts/Nexus-Platform-Physical-Architecture.py`](scripts/Nexus-Platform-Physical-Architecture.py), as the logical
drawing owns the sub-systems. This file owns the rule that relates the two catalogues. Parts belong to
[`../bom/BOM.md`](../bom/BOM.md), wiring and placement to [`../hardware/README.md`](../hardware/README.md) and the decisions;
the drawing names them and restates none of it.

## Merged and physical-only elements

The two catalogues are compared element by element, before any function is allocated:

- **Merged.** A physical element whose reason to exist is **one** sub-system is the physical side of that sub-system. It
  keeps the sub-system's `Nexus-SubSys-DNN` ID, has one definition and later one requirements file, and is drawn in the
  sub-system's domain colour. What it contributes to another sub-system is an allocation, not a second identity: SW1 is
  part of 101 and also serves 501 as the practical emergency stop (HW-08).
- **Physical only.** An element that serves several sub-systems, a compute node above all, has an ID of its own,
  `Nexus-Phys-NN`, numbered in order and never reused, and is drawn in slate.

A merge does not mean every function of the sub-system lives in that element. 101's state-of-charge estimate will run on
the STM32, and 301's detection on the Pi 5; allocation says so, the merge only says which element *is* the sub-system's
hardware.

**Sub-systems with no physical side of their own**: 203, 302, 303, 402, 403, 501, 502, 503 and 504. They are realised as
software on the nodes, and 501 partly by 101's switches and fuses. They reach the physical architecture only through
allocation, which is the next step.

## Not an element yet

- **The IMU** joins in Phase 2 only if it is bought ([phases.md](phases.md)); its connection is undecided.
- **Operator controls beyond SW1 and SW2.** Phase 2 puts vehicle status on the fascia LEDs; which hardware does that is open.
- **The Pi 5's power, mounting and network** wait for their own `HW` and `MEC` entries, as the phase plan says.
